CUDA 内存优化图解

从 CPU 与 GPU 之间的数据传输，到 GPU 内部的访存布局、缓存复用和分配策略。

本文按 NVIDIA《CUDA C++ Best Practices Guide》第十章的 10.1～10.4 组织，并结合 GEMM、TMA 和 Blackwell 的学习场景展开。核心目标是让读者能从代码推导出：数据在哪里、谁访问它、访问哪些地址、什么时候可以复用，以及为什么一种优化可能没有收益。

这是一份教学整理，不是原文逐句翻译。数值推演明确标为示例；历史平台的测试结论不作为 B300 的性能保证。CUDA 代码片段用于解释机制，除非另有说明，省略了错误处理与资源清理，没有声称经过 GPU 实测。

原文：第十章 Memory Optimizations。核对日期：2026 年 11 月 2 日。

10.1 主机与设备之间的数据传输

先区分两段数据路径

cudaMemcpyAsync 的 H2D/D2H 传输发生在主机内存与设备内存之间；前面学习的 TMA 和普通 cp.async，关注的是设备端 GMEM 到 SMEM 等路径。两者都可以组织流水，但控制接口、同步对象和性能瓶颈不同。

若 benchmark 预先把 A、B、C 放在 GPU，只测 GEMM kernel，那么 pinned memory 不会直接提升这项 kernel TFLOPS。测量从 CPU 输入到 CPU 输出的端到端耗时时，H2D、D2H 和主机准备才会进入结果。

减少往返优先于提高单次传输速度

原文强调：减少主机与设备传输，把中间数据留在设备，并尽可能合并小传输。原文 10.1

以 GEMM → 激活 → GEMM 为例，让三个操作连续在 GPU 执行，可以避免激活前下载、激活后上传。下面是自设的时间例子：

激活执行位置 激活计算 额外往返 合计
CPU 10 μs 200 μs 210 μs
GPU 20 μs 0 20 μs

10.1.1 Pinned memory

Pinned memory 是锁页或已注册的主机内存，仍然属于 CPU 侧内存。常用接口如下。

接口 作用 配对操作
malloc 普通主机分配 free
cudaMallocHost / cudaHostAlloc 分配 pinned 主机缓冲区 cudaFreeHost
cudaHostRegister 注册已有主机内存 cudaHostUnregister
cudaMalloc 分配设备内存 cudaFree

注册不等于把数据搬进 GPU；普通 pageable 内存的传输可能先经过驱动的 pinned 暂存区，增加一次暂存工作。复用预先分配好的 pinned buffer，能避免反复建立暂存路径。内存管理 API、API 同步语义

可以将输入缓冲区设计成生命周期较长的池：CPU 填入空闲 buffer，提交 H2D，确认传输完成后再改写它。Pinned 内存不应无限增加，锁页操作和占用主机资源都有成本。

10.1.2 异步不等于重叠

“异步”首先说明调用者可以在工作完成前继续执行；“重叠”说明两个工作在时间上同时推进。

同一个 stream 内，process 排在复制之后。CPU 的准备工作可以与设备工作重叠，但这个 kernel 不会越过同 stream 中尚未完成的输入传输。Async API 对 pageable 内存仍可能暂存或阻塞，不能简单理解为任何参数下都立即返回。API 同步语义

10.1.3 Zero Copy

Zero Copy 通过可访问的主机映射，让 kernel 直接读取主机侧数据，省去显式建立设备副本的步骤。映射能力和指针获取应按平台及 API 支持检查。Unified Addressing API

对只访问输入少量位置的算法，建立整个设备副本可能不划算；对反复复用权重 tile 的 GEMM，应比较预先上传后复用的方案。“没有显式 copy”并不意味着没有数据传输。集成式 GPU 或一致性互连系统需要用自身的缓存与内存模型判断，不能机械套用独立 PCIe GPU 的成本。

10.1.4 UVA 与 Unified Memory

UVA 统一虚拟地址空间，CUDA 可以查询指针的属性和所属设备，并在适当条件下推断复制方向。它不承诺任意处理器都能解引用任意指针，也不统一访问成本。Unified Addressing API

概念 可以怎样理解 不能据此推导
Pinned 主机内存适合注册和 DMA 传输 数据已驻留显存
Zero Copy 直接访问映射主机数据 跨链路成本消失
UVA 地址空间统一、指针可识别 自动迁移到最快位置
Unified Memory 系统管理可供 CPU/GPU 访问的内存 所有访问都像寄存器一样快

cudaMallocManaged 属于 Unified Memory 的接口。这里最重要的是把“地址能否表达”“处理器能否访问”“数据实际在哪里”三个问题分开。

10.2.2 L2 的热点窗口

先区分三个量：

量 描述

10.2.3.4 异步复制与 TMA

硬件支持的 GMEM→SMEM 异步复制可绕过搬运数据的中间寄存器，并与独立计算交错推进。普通 cp.async 的完成等待与线程间同步要匹配，不能只放一个 __syncthreads 就认为复制完成。CUDA 异步数据复制

项目 SM80 普通 cp.async SM90/SM100 TMA 张量搬运
常见发起方式 多线程分别指定小段地址 选定线程提交整个 tile
地址展开 程序计算各线程地址 tensor map 与坐标描述
SMEM 布局 软件计算目标地址 可配置硬件 swizzle
主要机会 减少中间寄存器、隐藏延迟 进一步减少地址和提交工作、组织 producer/consumer

这里的 TMA 补充来自设备端异步复制文档，不是第十章对 Blackwell 的完整介绍。TMA 的 GMEM→SMEM load 常用事务字节 barrier，store 使用不同完成机制；一个阶段既要确认数据到达，也要确认消费者用完后才能覆盖 buffer。

判断收益时，用两个问题代替“新指令是不是更快”：省掉的开销是否在关键路径？新增同步和资源占用是否抵消收益？若原本供数已被覆盖，计算吞吐不变，减少提交指令可能几乎不改变稳态时间。

Occupancy 是驻留 warp 比例，不是有用工作的比例。等待时间被隐藏与 latency-bound 相反：后者意味着等待仍限制了推进。高 occupancy 的 warp 可以一起等同一个依赖；低 occupancy 的深流水也可能保持足够多的在途操作。

10.2.4 Local memory

Local 表示线程私有，不表示位于片上。较大的局部对象、动态索引数组和寄存器 spill 都可能带来 local 存储。变量实际放在哪里取决于编译结果，不能看到 float a[64] 就认定它在寄存器。CUDA 线程私有存储

例如每线程使用一个动态索引的数组，再将每线程寄存器上限强行减小，可能让编译器增加 local load/store。评估时同时看编译报告中的寄存器、stack/spill 信息与实际耗时；只降低寄存器数字不是成功标准。

10.2.5 Texture memory

Texture 访问提供空间局部性相关缓存和采样功能，例如插值、坐标和边界模式。它不是与显存完全分离的一块神奇高速 RAM。对读图像的插值计算，这些功能可能直接省工作；对规则 GEMM，通常优先优化 tile、复用与流水。

不要在同一 kernel 中用普通 global store 改写纹理底层数据后，假定 texture fetch 会立即看到一致结果。应遵循具体纹理 API 的一致性约束。原文 Texture Memory

10.2.6 Constant memory

Constant 的关键是 warp 内有多少不同读取地址。所有 lane 读取同一个系数适合广播；每个 lane 都读不同常量，则需要考虑地址分歧带来的服务成本。

把“只读”与“warp 内访问相同”分开：大权重矩阵虽然只读，但并不自动适合 constant 空间。原文 Constant Memory

10.2.7 Registers

寄存器保存线程当前需要的操作数、地址和中间结果。每线程维护 8×8 个 FP32 累加值，就至少有 64 个数值需要容纳，此外还有索引和临时值。真实分配不能由源代码变量数直接等同得出。

更多累加器可以提高数据复用或独立计算量，也可能减少驻留并发；压低上限又可能产生 spill。float4 的潜在收益与向量化访存相关，不能简单解释为它必然减少寄存器 bank conflict。-maxrregcount 和 launch bounds 应作为实验变量，不是固定越小越好的旋钮。原文 Registers

10.3 内存分配

先考虑把工作区申请移出热循环：

若生命周期确实动态，stream ordered allocator 可以按 stream 顺序申请、使用和释放，并通过内存池复用存储。所有访问必须落在有效生命周期内。Stream Ordered Allocator API

CPU 拿到指针不代表另一条 stream 可以无依赖地开始访问。若 s1 分配、s2 消费，应在 s1 的分配之后记录 event，让 s2 等待；释放方还要等待 s2 的最后使用完成。

10.4 NUMA 与 GPU 邻近性

多 CPU 节点系统中，CPU 线程、主机内存页和 GPU 可能属于不同的拓扑位置。若 GPU 附近的 CPU 负责提交，却从另一节点的内存供数，数据可能额外经过 CPU 节点间互连。

因此，第十章中的节点列表示例不能直接复制为所有服务器的最佳设置。比较本地与远端内存供数时，应保持输入规模、pinned buffer、CPU 工作量与 GPU 工作相同，观察端到端时间和 H2D 带宽。只测一个完全驻留显存的长 GEMM，对主机 NUMA 变化可能不敏感。

容易得出的结论 更准确的判断
Async 代表两个工作一定同时执行 要同时满足依赖、资源和提交条件
Zero Copy 没有数据传输 省去显式副本，访问仍可能跨互连
单线程连续读取就是合并访问 固定一次指令，看整个 warp 的地址
GMEM 合并后 SMEM 一定也快 SMEM 要另外分析 bank 和消费布局
hitRatio 是实际命中率 它是访问属性分配提示
num_bytes 是预留的 L2 字节数 它是 GMEM 策略窗口的字节范围
local memory 在片上 local 指线程作用域
occupancy 越高越快 看是否存在可推进工作和足够在途请求
TMA 取代 cp.async 必然更快 看关键路径与新增资源成本
