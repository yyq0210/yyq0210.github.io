1. 论文定位与证据口径

论文：HySparse: A Hybrid Sparse Attention Architecture with Oracle Token Selection and KV Cache Sharing，arXiv:2602.03560。

  • 论文 PDF

本文区分三种内容：

类型 含义

补充分析 误差界、实现建议和研究方向；不是论文已经证明或实现的成果

核心结论：HySparse 把少数全注意力层作为全局信息选择者，让后续稀疏层复用其 KV 和选择索引。第一代还保留各稀疏层自己的局部 SWA 分支，因此它减少全局注意力工作量和全局缓存副本，却没有让长 prompt 直接跳过模型后半段的能力。

2. 为什么需要 HySparse

2.1 普通全注意力的两类成本

设序列长度为 ，层数为 。忽略批量和维度常数，普通 Transformer 的注意力 Prefill 成本随 增长；KV 存储随 增长。

这里仅写 attention 核心的量级，没有把投影、FFN/MoE、通信等省略成“零成本”。

2.2 只选少数 token，不会自动减少持久缓存

动态稀疏注意力本轮只读少数位置，但下一轮 Query 可能想读其他位置。如果每层都维护自己的全局 KV，就算单轮只读取 个位置，仍可能需要保存全部 个位置。

因此必须分别考虑：减少读了多少数据、减少算了多少 attention、减少存了多少份 KV。这三者不是一件事。

2.3 稀疏选择器也可能昂贵或不准确

许多方法额外训练轻量 indexer，或根据压缩表示、静态模式估计重要位置。它们的预测有误差，也可能引入训练目标、辅助损失和额外 kernel。

HySparse 的问题意识是：既然混合模型仍保留少数 FA，而且 FA 已经算出了真实注意力分数，为什么不复用这些结果，而要让后面每层独立预测一次？

3. 总体结构：一层找信息，后面几层重复加工

一层 Full Attention 生成本组全局 KV，并按当前 Query 选出重要块；后面的多层 Sparse Attention 复用这份 KV 和块索引，同时各自保留局部 SWA 分支。

基本分组为：

FA 做三件事：生成本组全局 KV，执行本层全注意力，产生当前 Query 的重要历史位置索引。后面的 SA 共享前两类数据产物中的 KV 和索引，但不共享 FA 的输出。

flowchart TD H["本组输入 hidden"] --> F["FA：生成 KV，执行全注意力"] F --> M["本组共享 Global KV"] F --> I["按当前 Query 得到 Top-K 块索引"] F --> FF["本层输出投影、残差与 FFN / MoE"] FF --> S1["SA 1：自己的 Query、局部 KV、门控、MoE"] S1 --> S2["SA 2：自己的 Query、局部 KV、门控、MoE"] S2 --> SN["后续 SA，沿层串行"] M -.-> S1 M -.-> S2 M -.-> SN I -.-> S1 I -.-> S2 I -.-> SN SN --> NEXT["下一组 FA：重新构建记忆并全局检索"]

复用不是整层跳过。每个 SA 仍有独立 Query、注意力权重、输出投影、残差和 FFN/MoE。

5.4 同一 token 出现在两条路径中，算重复吗

在 token 位置意义上可能重叠，但两套 K/V 是不同层、不同投影生成的表示。最近位置的全局 KV 不自动等于本层 SWA 的局部 KV。因此不能以“都是最近 128 个 token”为由直接删掉局部缓存。

第一代的实验恰好显示，强迫局部路径也使用源 FA 的 KV，在其配置下损伤质量。这是第二代必须重新训练和验证局部设计的原因。

6. Prefill 计算流水线

对一个冷启动 prompt，第一代通常要逐层处理所有位置：

  1. 某组 FA 对全部可见位置构建全局 KV，并执行全注意力。
  2. 为每个 Query 位置产生各自的块索引；不是整个 prompt 只有一份固定 Top-K。
  3. 第一个 SA 对全部位置生成 Query 和局部 KV，执行稀疏分支与局部分支，再执行 FFN/MoE。
  4. 后续 SA 继续逐层处理全部位置。
  5. 下一组 FA 用已经加工后的 hidden 生成新一组全局 KV。
  6. 最后位置的最终输出用于预测首个生成 token。

关键依赖为：

后面的全局 Writer 仍然需要前面各层 Reader/MoE 的结果；各 SA 自己的局部 Writer 也需要本层历史 hidden。所以共享组内 KV 不等于能让整个模型在前半段退出。

可以按 token chunk、不同请求或设备做流水线，但这只改变调度，不消除上述数学依赖。

7. Decode 计算流水线

对于当前新输入 token ：

  1. 到达 FA 时，根据本层 hidden 生成新 K/V，追加到本组全局缓存。
  2. 当前 Query 读取全部因果历史，执行 FA，并选择当前 token 的 Top-K 块。
  3. 后续每个 SA 生成自己的 Query，复用本组全局 KV 和本轮索引。
  4. 每个 SA 同时为自身 SWA 窗口写入当前 K/V，并淘汰窗口外的活动条目。
  5. 执行门控、输出路径和 MoE，继续下一层。
  6. 到下一组 FA 时，进行新的全局读取与选择。

选择索引通常是本轮、当前 Query 的临时结果，可以在组内复用；下一 token 到来后一般需要重新计算。不能把某轮未入选的位置永久删掉。

8. KV 生命周期和内存收益

8.1 哪些状态是长期的

状态 增长方式 生命周期
每个 FA 的全局 KV 随已处理 token 数增长 请求持续期间保留；如支持 prefix cache，可延长
每个 SA 的本层 SWA KV 窗口容量有界 Decode 时滚动更新
当前 Query 的 Top-K 索引 单轮产生 组内后续 SA 使用后可回收
Gather 后的临时连续 KV 取决于 kernel 可不物化，也可暂存；不必成为另一套长期缓存

“逻辑上拼接所选块”不要求每次在 HBM 中复制成完整连续大数组。实际 kernel 可通过 block table、索引或 gather 访问；物理布局属于实现选择。

8.3 Prefix caching 不是论文自动附送的功能

持有请求内 KV 与跨请求 prefix caching 是两个概念。若实现后者，需要考虑源 FA 的 global pages、各 SA 的局部窗口状态、位置/模型版本及部分块边界。只命中 global pages，并不自动恢复局部 SWA hidden 所对应的缓存。

不能把“请求结束”简单等同于“所有 KV 永久持久化”：无 prefix retention 时引用释放，有 retention 时按缓存策略保留。原论文没有提供完整 prefix cache 管理器。

9. 第一代与 PD 分离

PD 是 Prefill–Decode disaggregation：按请求阶段分离服务资源，不是按层深度切模型。

对第一代，可以采用普通 PD：P worker 运行完整骨干处理 prompt，D worker 安装缓存后运行完整骨干处理新 token。每个 worker 可以是一组做张量并行或流水线并行的 GPU。

P 到 D 至少需要交接供后续执行使用的全局 KV、局部 SWA 状态和必要元数据；如果首 token 尚未计算，还需明确交接哪个 hidden、输出头在哪运行。这是系统设计推导，不是第一代论文给出的已实现网络协议。

第一代节省的是全局 KV 副本和稀疏层工作量，不能因此宣称 P 只需要部署半个模型。HySparse2 的特殊收益来自额外切断后半层历史记忆的生成依赖。

论文也提出过 KV offloading 的潜力：FA 阶段读取全局 KV，后续 SA 只使用选中的部分。但把未选 KV 移到外部内存，意味着下一 FA 仍可能要访问它们；必须计算传输开销。这是探索方向，不是“已经验证无限上下文高吞吐”的结论。

即使所有 SA 读取同一份 ，也仍有不同的 、、FFN/MoE 和残差变换。其过程类似围绕同一批资料进行多轮加工，之后由下一 FA 根据更新后的表征重新全局检索。

保留的是多层计算，减少的是每层独立构建全长记忆和独立决定检索位置的自由度。

10.4 Oracle 究竟是什么意思

Oracle 指选择分数来自源 FA 的真实注意力，而不是另一个近似 indexer 对源 FA 的预测。

它不意味着源 FA 的 Top-K 对后续每个 SA 都是最优的，更不意味着它知道任务答案。后续层 Query 改变，最适合的位置也可能改变。共享索引的合理性仍依赖经验相关性和训练适应。

11.3 这没有覆盖哪些误差

12. 实验如何支持、又如何限制结论

12.1 主实验说明稀疏全局路径弥补纯局部混合的不足

原论文 80B、1:11 的设置中，Hybrid SWA 的若干指标相对全注意力下降明显。HySparse 加入稀疏全局读出后恢复或超过不少指标。例如 GSM8K 为全注意力 53.8、Hybrid SWA 45.3、HySparse 54.1；32k RULER 分别为 82.1、69.5、87.4。

但不是每个指标都获胜：例如 80B 的 16k RULER，HySparse 90.6 低于全注意力 93.6。结论应是给定训练设置下总体具有竞争力，而不是“逐项严格优于”。

12.3 第一代与第二代不矛盾

第一代发现独立 SWA 有价值；第二代仍承认删除独立局部表示会在部分任务损失质量，但接受这种取舍，以换取更少投影、局部缓存和后半模型历史依赖。

第二代 Forced SWA 不是第一代两分支的代数等价重写。它改变了 KV 来源与归一化结构，需要重新训练和验证。

13. 与 MLA–KDA CED 的关联

今天把两篇论文联系到此前的研究想法时，区分了三个独立问题：

  1. Writer 输入在哪里产生？从本层 hidden 改成 Encoder hidden，可以消除部分层间依赖。
  2. 有多少独立 Writer 和状态？共享输入不等于共享状态；HySparse 的组内 Reuse 才进一步减少记忆副本。
  3. Reader 是否依赖本层历史 hidden？若有 Q 短卷积或独立 SWA，仍可能需要尾部执行。

第一代主要解决第 2 项以及选择结果复用；HySparse2 又解决第 1 项并改变第 3 项。

此前的 KDA 方案把各层 Writer 接到同一 ，各层状态仍独立。若保留宽度 的 Query 卷积，后半有 个此类层，理想化局部依赖下的最后位置输入覆盖长度为：

例如 时为 100。这个数字是先前特定方案的依赖推导，不是 HySparse 的参数，也不是所有混合模型通用常数。HySparse2 后半没有这种本层历史 Query 卷积或独立 SWA KV 依赖，所以不能把 100-token 规则套给它。

14. 可落地的系统检查项

以下是由计算图提出的工程检查，不是原论文性能承诺：

  • 检查 FA 输出块分数的额外写流量与 Top-K 开销。
  • 检查 GQA 共享索引和 paged KV 的物理映射是否一致。
  • 检查 SA 重复读取同一组 KV 时能否复用 staging buffer，而不错误复用 Query 或输出。
  • 区分持久 KV、局部环形缓冲、临时索引和临时 gather 的内存峰值。
  • 对比 Prefill FLOPs、实测 TTFT、单 token 延迟、吞吐和网络流量，不能只报一个理论倍率。
  • 长上下文测试应测保留注意力质量与输出误差，而不只看 token overlap。
  • 若做跨请求 prefix cache，必须保存或正确恢复独立 SWA 状态。
  • 若做 offload，必须计入 FA 再次全局访问的代价。

八、作者为什么能想到 HySparse？它的理论依据是什么？

先直接回答：

HySparse 主要建立在经验观察、已有架构结果和消融实验之上，不是先证明了一个“共享之后一定不掉质量”的定理，再据此设计模型。

原文明确给出两条来源：

  1. 相邻层的重要 token 具有一定稳定性。
  2. 跨层共享 KV 在已有实验中可行。

十、作者通过什么实验确认设计？哪些结论不能过度解读？

1. 第一版不是“一开始就知道局部路径可以省”

HySparse 的消融显示，在相关 7B 实验中：

  • 加入独立 SWA，GSM8K 从 29.7 到 37.7；
  • 让 SA 和 SWA 都共享 KV，相比只让 SA 共享，GSM8K 从 36.7 降到 30.2。

所以第一版得到的是：

在当时的配置中，独立局部路径有价值，最大化共享会损害质量。

这属于受配置限制的实验结论，不是“局部 KV 永远不能共享”的定理。 HySparse 表 4

2. 第二版并没有证明删除独立 SWA 完全无损

HySparse2 对比独立 Gated SWA 与 Forced SWA：

  • Forced SWA 在部分检索、图推理指标更好；
  • 但 GSM8K 下降 5.08 点；
  • MRCR-v2 下降 4.99 点。

作者认为，换来更少参数、更简单缓存和完整 Prefill 早退，这是可以接受的取舍。

因此，两篇论文并不矛盾：

第一版验证了独立局部表示的价值；第二版选择牺牲一部分局部表达自由度，换取更大的系统收益。

3. token-level 的优势来自更细的预算分配

固定选择 1024 个全局 token：

  • block-level：最多选 16 个长度 64 的块；
  • token-level：可以把预算分散给大量不同位置。

若多个重要标识符、角色边界、工具结果分散在不同块里，block-level 会把预算花在大量邻居上。

论文的消融支持 token-level 在相关长上下文任务上更好，但这并不意味着所有一般能力指标都同步上升。

4. 为什么选 FA 输入 hidden 做 Bridging？

作者给出的解释是：

FA 的训练梯度通过全局可见的注意力连接传播，使其输入表示受到更全局的监督；SWA 的直接连接范围更局部。

这是一个机制假说。Bridging 相比 KV Mirror 的实验支持这个连接选择，但没有排除所有其他因素。

特别注意：

“FA 的输入 hidden 受到全局训练监督”，不等于“它在本次前向中已经经过这个 FA 的全局聚合”。

输入和输出不能混淆。

5. “有效”也不等于全面无代价

HySparse2 的结果主要支持：

  • 更低的 Prefill 计算预算；
  • 更小的缓存；
  • 在其长上下文、Agent 数据与评测设置中更强的表现；
  • 一般能力整体接近，但存在任务间得失。

它没有证明：

  • 任意已有模型都能无训练改成这个架构；
  • 任意共享比例都有效；
  • FLOPs 降低必然转化为同倍延迟降低；
  • 当前 PD、异步投机解码方案已经获得端到端系统实测加速。

原文段落：与 MLA–KDA CED 的联系

最后，联系你的 MLA–KDA CED 想法

HySparse2 给你的最直接启发不是“所有记忆都共享”，而是把三个设计问题分开：

  1. Writer 输入从哪里来？
    Bridging：从前半模型拿 hidden，让 Writer 提前可执行。

  2. 多少层共用一份记忆？
    Reuse：减少独立 Writer 和缓存副本。

  3. Reader 是否还依赖本层历史 hidden？
    这决定能否只算最后位置，还是需要 100-token 之类的依赖补齐。

你的原方案保留本层 Q 短卷积，所以第三项依赖仍在。

HySparse2 则把后半段的局部信息需求也改成了读取前半段生成的记忆，从计算图上去掉这条历史 hidden 依赖。

可以把整条研究思路概括为：先利用层间冗余少建记忆、少做检索，再切断历史 hidden 对未来缓存构建的依赖，最终让大部分历史 Reader 变成真正可以不执行的计算。
